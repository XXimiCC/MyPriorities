# Сдача видимой работы

Зелёные тесты доказывают, что код работает. Они не показывают, **как это
выглядит** и **как до этого добраться**. Человек, который принимает работу,
открывает приложение и не находит того, что вы сделали, — и сдача не состоялась,
хотя код в порядке.

Поэтому итоговый комментарий по любой задаче, изменившей интерфейс, состоит из
трёх обязательных частей. Ни одна не заменяет другую.

## 1. Что сделано

Словами, коротко: что появилось, где живёт, по какому правилу показывается.
Файлы — списком. Это уже привычная часть, здесь ничего нового.

## 2. Снимки функционала

Снимок — не украшение комментария, а доказательство. Снимайте **сам
функционал**, а не соседний экран, и столько кадров, сколько состояний у фичи.

Минимальный набор для шторки, формы или экрана:

- обычное состояние — то, что человек увидит в обычном случае;
- граничное или запертое состояние, если оно есть (поле не проходит проверку,
  кнопка заблокирована, пустой список);
- **результат** — экран после действия, где видно, что запись действительно
  произошла. Без этого кадра фича доказана наполовину;
- узкий экран 320 × 568, если что-то могло не поместиться.

### Снимайте настройками репозитория, а не «как получится»

Здесь уже есть рабочая съёмочная обвязка — `tools/shots/capture.mjs`, описана
в `docs/dev/screenshots.md`. Разовый скрипт для своей фичи пишите **по её
образцу** и копируйте настройки контекста целиком.

Самая дорогая из них — `reducedMotion: 'reduce'`.

> Шторки въезжают анимацией `sheet-rise` за 0.28 с с `opacity: 0 → 1`, а
> затемнение фона — `sheet-fade` за 0.2 с. Кадр, снятый посреди анимации, даёт
> полупрозрачную панель, сквозь которую читается фон. Приложение схлопывает
> анимации до 0.01 мс в `@media (prefers-reduced-motion)` (`src/styles/global.css`),
> поэтому под `reducedMotion: 'reduce'` шторка стоит на месте уже в первом кадре.

Готовый образец — `capture-template.mjs` рядом с этим файлом. Кладите свою копию
в `tools/shots/` (иначе не разрешится `playwright`), выводите PNG в `.shots/`,
и **не коммитьте** ни то, ни другое: это рабочая оснастка одной сдачи.

```bash
npm run shots:setup                       # один раз: playwright + chromium
npm run build                             # снимаем собранное, не dev-сервер
node tools/shots/<моя-фича>.local.mjs
```

Язык кадров — язык задачи. Локаторы тогда тоже берутся из нужной локали:
`?lang=ru` и русские подписи, `?lang=en` и английские.

### Посмотрите на кадр перед тем, как приложить

Обязательный шаг, а не формальность. Откройте каждый PNG инструментом Read и
спросите себя:

- текст читается, панель непрозрачна, фон не просвечивает сквозь неё?
- в кадре видно **то самое**, что вы сделали, а не только шапка экрана? Если
  нужное ниже сгиба — домотайте `scrollIntoView({ block: 'center' })`;
- нет случайного мусора: панели отладки (`devkit=0`), курсора в поле, всплывшей
  плашки достижения поверх главного?

Кадр, на котором не видно фичи, хуже отсутствия кадра: он создаёт видимость
проверки.

Прикладываются кадры так — путь в рабочем каталоге ссылкой быть не может,
только вложением:

```bash
multica issue comment add <issue-id> --parent <comment-id> --content-file ./reply.md \
  --attachment ./.shots/01-....png --attachment ./.shots/02-....png
```

## 3. Как открыть и проверить руками

Пошаговый маршрут от запуска до результата. Пишите его так, чтобы человек,
который не читал ваш код, дошёл до конца, ни разу не догадываясь.

Каждый шаг — одно действие: **где** и **на что** нажать, **что** ввести, **что**
должно появиться. Не «включите демо-режим», а «откройте `/?mock=1`». Не
«дождитесь утра», а «как перевести часы, чтобы не ждать сутки».

Отдельно назовите:

- команду запуска и адрес (`npm run dev`, `http://localhost:5173/?...`);
- условия, без которых фича не покажется, — и как их создать;
- как вернуть всё в исходное, если проверку захотят повторить (обычно —
  очистить хранилище сайта в DevTools → Application, приложение local-first).

Если довести до состояния руками дороже пары минут — скажите об этом честно и
дайте вместо ручного маршрута сквозной тест, который проходит тот же путь:
`npm run test:e2e -- <файл>`. Но сначала попробуйте маршрут: чаще всего его
можно сократить параметром адреса или переводом часов в DevTools.

## Чего не делать

- Не заменять снимки описанием. «Выглядит аккуратно» — не доказательство.
- Не снимать dev-сервер: HMR-клиент и оверлей ошибок попадают в кадр.
- Не прикладывать кадр, на который вы сами не посмотрели.
- Не писать абсолютный путь к файлу как ссылку — у читателя этой машины нет.
