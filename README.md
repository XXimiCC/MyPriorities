# Мои Приоритеты

Telegram Mini App: список приоритетов на главном экране, один клик — тридцать минут
жизни, вложенных в направление. Плюс личная «батарея» заряда, лестница навыков,
достижения и генератор обоев с состоянием заряда.

React 18 + TypeScript + Vite. Из runtime-зависимостей только `react`, `react-dom`
и — единственным исключением — `modern-screenshot` во встроенной панели отладки,
где он приезжает отдельным ленивым куском ([подробнее](docs/dev/devkit.md)).
Ни роутера, ни менеджера состояния, ни библиотек графиков и перетаскивания.
Данные живут на устройстве в IndexedDB журналом операций; синхронизация между
устройствами — необязательная, через Cloudflare Worker и D1 ([`worker/`](worker/)).

Визуальный язык взят из [references/](references/): чистый чёрный фон, неоновая
трёхсегментная батарея, подпись капсом с широким трекингом между двумя тонкими
линиями. Приложение намеренно только тёмное — тема Telegram игнорируется, иначе
дизайн ломается.

## Команды

```bash
npm install
npm run dev          # http://localhost:5173
npm run dev          # + ?mock=1 или ?demo=max — демо-профили, запись отключена
npm run test         # логика приложения и связность документации
npm run build        # tsc --noEmit + сборка в dist/

npm run docs:dev     # сайт документации
npm run docs:build

npm run landing:dev  # лендинг
npm run landing:build
npm run landing:sync # обновить копии токенов и кадров в landing/

npm run shots:setup  # один раз: playwright + chromium
npm run docs:shots   # пересобрать скриншоты документации
npm run brand        # пересобрать иконки, фавиконы и превью ссылки

npm run devkit:sync  # пересобрать панель отладки для документации и лендинга
npm run tickets:list # тикеты из встроенной панели отладки
npm run tickets:pull # забрать их в .tickets/ — оттуда их читает нейронка
npm run tickets:close -- <id> "что сделано"
```

## Структура

```
src/
  i18n/          строки интерфейса и правила множественного числа
  domain/        типы, палитра, даты, наборы, агрегация, наблюдения
  store/         схема хранения, сериализация, стор с отложенной записью
  telegram/      обёртка над WebApp и хранилище «ключ — значение»
  components/    батарея, строка приоритета, шторка, графики, перетаскивание
  demo/          профили «показать другу» и их генератор
  screens/       десять экранов
  skills/        лестница ступеней, подсчёт часов, строка и шторка навыка
  achievements/  реестр, предпосчёт, выдача, карточка для «поделиться»
  wallpaper/     canvas-рендер и сохранение
  sync/          журнал операций, метки, обмен с сервером, разовый перенос
  platform/      сессия и то, что различается между браузером и обёрткой
  devkit/        переносимая панель отладки: кадр, разметка, тикет

worker/          сервер синхронизации и тикеты (Cloudflare Worker + D1, свой package.json)
docs/            сайт документации (VitePress, свой package.json и деплой)
landing/         публичная страница приложения (Vite, свой package.json и деплой)
tools/shots/     генератор скриншотов и иконок (Playwright)
tools/tickets/   командная строка для тикетов панели отладки (только node)
public/          манифест PWA, иконки, service worker — собираются `npm run brand`
```

`tsconfig.json` включает только `src`, поэтому `docs/`, `landing/`, `worker/` и
`tools/` в сборку приложения не попадают, а VitePress, Vite лендинга, wrangler и
Playwright живут в собственных `package.json` — корневая установка зависимостей
от них не растёт. Каждый из этих каталогов деплоится отдельным проектом.

## Безопасность

**Бот-токен приложению не нужен.** Мини-апп работает целиком на клиенте; токен
нужен только для серверных вызовов Bot API и в бандле стал бы публичным.
В репозитории его нет и быть не должно.
