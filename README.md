# Мои Приоритеты

Telegram Mini App: список приоритетов на главном экране, один клик — тридцать минут
жизни, вложенных в направление. Плюс личная «батарея» заряда, лестница навыков,
достижения и генератор обоев с состоянием заряда.

React 18 + TypeScript + Vite. Из runtime-зависимостей только `react` и `react-dom`:
ни роутера, ни менеджера состояния, ни библиотек графиков и перетаскивания.
Бэкенда нет — данные лежат в Telegram CloudStorage.

Визуальный язык взят из [references/](references/): чистый чёрный фон, неоновая
трёхсегментная батарея, подпись капсом с широким трекингом между двумя тонкими
линиями. Приложение намеренно только тёмное — тема Telegram игнорируется, иначе
дизайн ломается.

## Команды

```bash
npm install
npm run dev          # http://localhost:5173
npm run dev          # + ?mock=1 или ?demo=max — демо-профили, запись отключена
npm run test         # логика приложения и связность документации
npm run build        # tsc --noEmit + сборка в dist/

npm run docs:dev     # сайт документации
npm run docs:build

npm run shots:setup  # один раз: playwright + chromium
npm run docs:shots   # пересобрать скриншоты документации
```

## Структура

```
src/
  i18n/          строки интерфейса и правила множественного числа
  domain/        типы, палитра, даты, наборы, агрегация, наблюдения
  store/         схема хранения, сериализация, стор с отложенной записью
  telegram/      обёртка над WebApp и хранилище «ключ — значение»
  components/    батарея, строка приоритета, шторка, графики, перетаскивание
  demo/          профили «показать другу» и их генератор
  screens/       десять экранов
  skills/        лестница ступеней, подсчёт часов, строка и шторка навыка
  achievements/  реестр, предпосчёт, выдача, карточка для «поделиться»
  wallpaper/     canvas-рендер и сохранение

docs/            сайт документации (VitePress, свой package.json и деплой)
tools/shots/     генератор скриншотов для документации (Playwright)
```

`tsconfig.json` включает только `src`, поэтому `docs/` и `tools/` в сборку
приложения не попадают, а VitePress и Playwright живут в собственных
`package.json` — корневая установка зависимостей от них не растёт.

## Безопасность

**Бот-токен приложению не нужен.** Мини-апп работает целиком на клиенте; токен
нужен только для серверных вызовов Bot API и в бандле стал бы публичным.
В репозитории его нет и быть не должно.
